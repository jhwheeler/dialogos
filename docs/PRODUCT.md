# Dialogos — Product Overview

## Introduction

This document captures the design thinking for an audio-first learning app focused on **oral mastery**, **Socratic questioning**, and **classical structure** (especially the trivium: grammar, logic, rhetoric).

**Working brand name:** **Dialogos**

Rationale: the name signals dialogue + logos (truth-oriented speech/reason), which better fits the product philosophy than the earlier codename "Rhetoric Gym."

The idea emerged from a tension:

- modern tools (especially AI) can be useful,
- but they can also **offload the very thinking-work that produces learning**.

The core principle we are designing around is:

**The app should help the user think, speak, recall, and organize — but it should not do the synthesis for them.**

This is aimed at self-learners (philosophy, theology, languages, technical topics, etc.), and could eventually also be useful for educators, but the first target is the serious autodidact who wants formation, not just content consumption.

---

## The Core Tension We Want to Preserve

### What we want to avoid

We do **not** want an app that:

- summarizes the text for the user,
- generates the user's notes,
- writes their argument for them,
- flatters them with vague praise,
- becomes a dopamine app / scrolling app.

That kind of product helps with output throughput, but undermines learning when the goal is formation.

### What we do want

We want an app that acts like a:

- **coach**
- **examiner**
- **sparring partner**
- **metronome / structure enforcer**

The user does the intellectual labor.
The AI provides constraints, pressure, and feedback on form.

---

## Product Thesis

### Working thesis

An **audio-first dialogic oral-practice app** that helps people internalize what they are learning by speaking it from memory, under structured prompts and Socratic questioning.

It is not a note-taking app, not a speech-polish app, and not a debate chatbot.
It is a **formation tool** for:

- retrieval
- articulation
- conceptual clarity
- argument structure
- rhetorical flexibility

### Core differentiator

The differentiator is the combination of:

1. **Trivium-based progression** (grammar → logic → rhetoric)
2. **Socratic questioning** (respectful, sharp, anti-sycophantic)
3. **Audio-first, low-screen UX**
4. **Anti-offloading AI constraints** (AI does not generate the content)

## Educational / Philosophical Spine

This section summarizes the educational themes informing the product.

### 1) Ancient Greek education (Socratic / rhetorical formation)

Key insight:

- Learning is shown in **speech**, especially under questioning.
- Socratic method tests whether someone truly understands or only repeats words.
- There is a longstanding anxiety about writing as external storage that can weaken internalization (relevant to modern AI concerns).

Product implication:

- The unit of learning should be a **spoken performance under constraints**, not a written summary generated by the app.

### 2) Medieval education (Trivium + disputation)

Key insight:

- Grammar, logic, rhetoric are not just subjects; they are a **sequence of cognitive acts**.
- Disputation formalizes objection / response as a path to clarity.

Product implication:

- Sessions should be explicitly structured around **trivium moves** and **objection-response drills**.

### 3) Renaissance humanism (language + rhetoric + source texts)

Key insight:

- Philology, source texts, and rhetoric are linked.
- Deep learning often happens through close engagement with original or primary sources.

Product implication:

- The app should support source-based practice (book pages, passages, texts), but remain domain-agnostic.

### 4) Enlightenment method (clarity + explicit reasoning)

Key insight:

- Good thinking requires method, definitions, and explicit structure.

Product implication:

- The app should enforce clarity (define terms, identify claims, state premises), while avoiding sterile over-formalization.

### 5) Waldorf / oral-formational pedagogy (selectively applied)

Key insight:

- Rhythm helps learning become a practice, not a motivation contest.
- Oral recall, recitation, retelling, and imitation help material become internal.
- Abstract analysis lands better after the material is alive in the learner.
- We can use these pedagogical strengths without importing anthroposophical metaphysics or rigid developmental dogma.

Product implication:

- Sessions should have a **stable flow** (arrival → recall → trivium work → compression → closure), while staying short and flexible.
- The app should include recall/retell/paraphrase moves before heavy analysis when appropriate.
- The UX should feel calm, low-stimulus, and formative rather than gamified.

### 6) Romantic / Montessori / self-directed education line

Key insight:

- Education can become dehumanizing when it turns into external control and standardization.
- Self-direction matters.

Product implication:

- UX should feel like a **dojo / practice environment**, not a school dashboard.
- The user should choose topics and sources; the app provides form and pressure.

### 7) Anti-Prussian / anti-factory schooling stance

Key insight:

- Standardization and compliance are often mistaken for education.

Product implication:

- Avoid grades-first design.
- Focus on **practice quality** and **consistency**, not institutional reporting.

## Trivium as Product Protocol

We are not using "trivium" as branding fluff.
We are using it as a **session protocol**.

### Grammar stage (what is being said?)

The user must perform acts like:

- define key terms
- identify a central claim
- quote or paraphrase a key sentence
- distinguish similar terms

### Logic stage (how does it hold together?)

The user must perform acts like:

- state premises and conclusion
- identify assumptions
- give the strongest objection
- locate uncertainty (weak premise / unclear inference)

### Rhetoric stage (can you express and defend it?)

The user must perform acts like:

- explain it to a specific audience
- state a position
- persuade, compare, or defend
- respond to cross-examination

This protocol is the heart of the product.

## Socrates Mode (non-negotiable behavior/tone requirement)

### Desired tone

- respectful
- precise
- unsentimental
- occasionally witty
- not mean
- not flattering

### Must avoid

- "Great job!" / "You're absolutely right!" style sycophancy
- fake encouragement
- content-padding

### Socrates Mode behavior examples

- asks for definitions before proceeding
- points out equivocation
- asks for distinctions
- presses on unstated assumptions
- asks for a concrete example
- asks whether the user is contradicting themselves
- asks the user to restate more clearly

This should feel like being challenged by a sharp tutor, not praised by a motivational app.

## Core Loop (MVP version)

### Session flow (10–15 minutes)

1. **Choose source**
   - A passage, chapter, concept, lecture, or topic
2. **Arrive / orient (brief)**
   - one short prompt to anchor attention (e.g. "What are you working on?")
3. **Recall by voice** (default)
   - from memory first: retell, define, or paraphrase before checking notes
4. **Choose mode**
   - Grammar / Logic / Rhetoric (or a combined sequence)
5. **Receive Socratic follow-up**
6. **Compression**
   - restate in one clear sentence (or one analogy, if rhetoric mode)
7. **Closure**
   - name what is still unclear / what needs another pass
8. **Export transcript + structure** (optional)

### Important MVP constraint

Feedback should mostly be about:

- clarity
- completeness
- structure
- coherence
- precision

It should **not** default to giving the answer.

Waldorf influence in MVP should stay at the **session-flow level** (rhythm, recall, paraphrase, closure), not expand into block schedules, grade-level schemas, or a large curriculum system.

## Source Input / Context Ingestion

The app needs easy ways to give the AI context **without requiring phone typing**.

### Preferred input methods

1. **Take a picture of a page**
   - photo of book page / notes / printout
2. **Upload a document**
   - PDF, text file, image
3. **Name a public source verbally**
   - e.g. "Plato Republic Book 1" or "John 1 in Greek"
4. **Record a verbal source summary**
   - if no text is available, user can say what they're working on

### Secondary fallback (optional)

- typing on phone should exist but not be the main path
- text mode should be possible for quiet/noisy environments

### Product principle

The main path should be:
**audio + image/document**, not phone keyboard.

## What the AI Is Allowed to Do vs Not Do

### AI may do

- transcribe
- ask structured prompts
- enforce the trivium protocol
- ask Socratic follow-ups
- identify missing elements (undefined term, no objection, no conclusion)
- reflect back the user's own wording
- score or tag formal qualities (clarity, completeness, drift, equivocation)

### AI may not do (default behavior)

- summarize the source for the user
- produce the user's argument
- generate a polished response on the user's behalf
- auto-fill trivium slots
- praise the user just to be pleasant

This distinction is central to the product identity.

## MVP Feature Set

### Must-have

- Audio recording and playback
- Speech-to-text transcription
- Source ingestion (photo + document + simple source naming)
- Session templates:
  - Grammar Drill
  - Logic Drill
  - Rhetoric Drill
  - Combined Trivium Session
- Socrates Mode follow-up questioning
- Minimal rubric feedback (form, not content)
- Session transcript export (Markdown / plain text)

### Nice-to-have (not MVP)

- spaced resurfacing ("Explain this again in 3 days")
- custom user-created drills
- friend sparring mode
- teacher mode / classroom mode
- advanced rhetorical rubrics
- embodied / somatonoetic module (deferred)

---

## Why Somatonoetics Is Deferred

Somatonoetics is philosophically aligned with this project (formation, embodiment, integration), but for MVP it adds too many moving parts.

Reasons to defer:

- additional UX complexity
- more state tracking
- harder onboarding
- unclear MVP fit for broad users

Possible future use:

- optional "Embodied Rhetoric" mode where users mark bodily state before/after speaking
- pattern detection over time (e.g., confusion, agitation, avoidance)

For now: keep the product lean and focused on oral learning.

## Competitive Positioning

### What this is NOT

- not a public speaking polish app (filler words, charisma metrics)
- not an AI debate toy
- not a note-taking app
- not a flashcard app
- not a course platform

### What this IS

A **practice environment for oral understanding**:

- recall from memory
- speak clearly
- define terms
- survive objections
- develop intellectual self-possession

### Market framing options

- self-learners / autodidacts
- classical education / homeschool / rhetoric communities
- philosophy / theology students
- language learners (later, via adapted modes)
- educators (later, if assessment layer is added)

## Language Learning Extension (future, but promising)

There is a promising adjacent direction:

- combining **composition + correction + shadowing**
- integrating speech drills into daily life (e.g., tense practice on real actions)

Examples:

- user describes an action in present/past/future
- AI gives one correction and asks for repeat
- AI does not start a free-form chat; it keeps the drill constrained

This is likely a separate mode or later product branch.
For MVP, keep focus on rhetoric/trivium oral practice.

## UX Notes

### UX goals

- low screen time
- low friction
- feels like a training bell, not a social app
- rhythmic and repeatable (same flow, different content)
- mostly usable by voice
- works during walks / tea / study sessions

### UX style

- minimal visual clutter
- short prompts
- strong defaults
- no infinite feed
- no cartoon gamification

### Interaction pattern

- short session prompts
- one follow-up at a time
- one correction at a time
- clear next action

This should feel closer to a dojo or oral exam than to Duolingo or ChatGPT chat.

## Suggested Session Types (v1)

### 1) Define and Distinguish (Grammar)

Prompt examples:

- "Define term A."
- "Distinguish A from B."
- "Quote or paraphrase one key sentence."

### 2) Argument Skeleton (Logic)

Prompt examples:

- "State the argument as premises and conclusion."
- "Which premise is weakest?"
- "Give the strongest objection."

### 3) Explain to X (Rhetoric)

Prompt examples:

- "Explain this to a smart teenager."
- "Explain this to someone who disagrees."
- "Use one analogy."

### 4) Recall / Retell / Paraphrase (Waldorf-informed)

Prompt examples:

- "Retell the core idea in your own words without looking."
- "Paraphrase the key sentence more plainly."
- "Say it again, but more exactly."
- "Repeat the claim, then give one concrete image or example."

### 5) Socrates Mode Cross-Exam

Prompt examples:

- "You used the word 'justice.' Define it."
- "Are you making the same claim or a different one now?"
- "What follows if your premise is false?"

### 6) Trivium Sequence (Combined)

A guided 10-minute sequence:

1. brief arrival
2. recall / retell
3. grammar
4. logic
5. rhetoric
6. short cross-exam
7. compression + closure

---

## Early Product Rules (non-negotiable)

1. **No sycophancy**
2. **No auto-synthesis by default**
3. **Audio-first**
4. **Source-grounded** (user should be anchored to a text/topic)
5. **Short sessions** (high repeatability)
6. **Rhythmic flow** (stable session pattern, flexible content)
7. **Formative, not factory-style assessment**

## Open Questions for Next Iteration

1. **Platform choice for MVP**
   - Telegram bot vs PWA vs native app
   - Telegram is fast to ship, but may limit UX polish

2. **Source ingestion complexity**
   - How much OCR / text extraction is needed in v1?
   - Should users be able to just speak the source summary and skip OCR entirely?

3. **Feedback rubric design**
   - What are the minimum useful rubric categories?
   - How to make them strict but not annoying?

4. **Session memory / continuity**
   - Should Socrates Mode remember prior answers in the same source and call out contradictions?

5. **Export flow**
   - Best handoff to writing workflows (Markdown, Obsidian, email, Notion)

6. **Pricing / monetization**
   - Cheap and accessible is the goal
   - likely free tier + simple paid tier
